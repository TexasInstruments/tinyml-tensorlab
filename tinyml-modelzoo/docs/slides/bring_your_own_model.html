Quick Start: Point the Config at Your Own File
No edits to tinyml-modelzoo. Works with the wheel install too. The full train, ONNX export and compile pipeline runs
1 · Your model file
# /path/to/my_model.py import torch.nn as nn class MyModel(nn.Module): def __init__(self, variables=1, num_classes=2, input_features=512, **kwargs): super().__init__() self.net = nn.Sequential( nn.Flatten(), nn.Linear(variables * input_features, 64), nn.ReLU(), nn.Linear(64, num_classes)) def forward(self, x): # x: (batch, variables, input_features, 1) return self.net(x) # (batch, num_classes)
2 · Config
training: model_name: MyModel # = class name custom_model_path: /path/to/my_model.py quantization: 2 # optional: QAT + hardware NPU
3 · Run
./run_tinyml_modelzoo.sh config.yaml # or, from any folder: python -m tinyml_modelmaker.run_tinyml_modelmaker config.yaml
Two styles, detected automatically
Plain nn.Module (gets variables, num_classes, input_features keyword arguments) or a GenericModelWithSpec subclass (gets config=dict(...)).
What you get
quantization unset: float model in training/base/, compiled to mod.a (soft NPU). quantization: 2: also training/quantization/, compiled for the hardware NPU.
Watch out
Class name must equal model_name. The model must return (batch, num_classes). Needs a ModelMaker release with custom_model_path; otherwise the run stops with please check if the given model_name is a supported one.

Step 1 · Add the Model Class: Two Ways
The same model written both ways: identical layers, 1,700 parameters and the same ONNX graph. Pick one and add it to models/classification.py
Option ASpec-based: GenericModelWithSpecRecommended
class MY_CNN_TS_2K_NPU(GenericModelWithSpec): def __init__(self, config, input_features=512, variables=1, num_classes=2): super().__init__(config, input_features=input_features, variables=variables, num_classes=num_classes) self.model_spec = self.gen_model_spec() self._init_model_from_spec( model_spec=self.model_spec, variables=self.variables, input_features=self.input_features, num_classes=self.num_classes) def gen_model_spec(self): layers = py_utils.DictPlus() layers += {'0': dict(type='BatchNormLayer', num_features=self.variables)} layers += {'1': dict(type='ConvBNReLULayer', in_channels=self.variables, out_channels=8, kernel_size=(5, 1), stride=(1, 1))} layers += {'2': dict(type='MaxPoolLayer', kernel_size=(2, 1), stride=(2, 1), padding=(0, 0))} layers += {'3': dict(type='ConvBNReLULayer', in_channels=8, out_channels=16, kernel_size=(5, 1), stride=(1, 1))} layers += {'4': dict(type='MaxPoolLayer', kernel_size=(2, 1), stride=(2, 1), padding=(0, 0))} layers += {'5': dict(type='ConvBNReLULayer', in_channels=16, out_channels=16, kernel_size=(3, 1), stride=(1, 1))} layers += {'6': dict(type='AdaptiveAvgPoolLayer', output_size=(4, 1))} layers += {'7': dict(type='ReshapeLayer', ndim=2)} layers += {'8': dict(type='LinearLayer', in_features=16 * 4, out_features=self.num_classes)} return dict(model_spec=layers)
Option BNative PyTorch: torch.nn.Module
class MY_CNN_TS_2K_NPU(torch.nn.Module): def __init__(self, config, input_features=512, variables=1, num_classes=2): super().__init__() variables = config.get('variables', variables) num_classes = config.get('num_classes', num_classes) self.features = torch.nn.Sequential( torch.nn.BatchNorm2d(variables), torch.nn.Conv2d(variables, 8, kernel_size=(5, 1), padding=(2, 0)), torch.nn.BatchNorm2d(8), torch.nn.ReLU(), torch.nn.MaxPool2d(kernel_size=(2, 1), stride=(2, 1)), torch.nn.Conv2d(8, 16, kernel_size=(5, 1), padding=(2, 0)), torch.nn.BatchNorm2d(16), torch.nn.ReLU(), torch.nn.MaxPool2d(kernel_size=(2, 1), stride=(2, 1)), torch.nn.Conv2d(16, 16, kernel_size=(3, 1), padding=(1, 0)), torch.nn.BatchNorm2d(16), torch.nn.ReLU(), torch.nn.AdaptiveAvgPool2d((4, 1)), ) self.classifier = torch.nn.Linear(16 * 4, num_classes) def forward(self, x): x = self.features(x) return self.classifier(x.reshape(x.shape[0], -1))
Option A: the base class fills in variables, input_features and num_classes. Spec layers pad k // 2 by default, so pass padding=(0, 0) on the pools.
Option B: read variables and num_classes from the config dict. PyTorch does not pad by default, so set padding=(k // 2, 0) on each Conv2d to match Option A.
Either way, add 'MY_CNN_TS_2K_NPU' to __all__. torch, py_utils and GenericModelWithSpec are already imported at the top of models/classification.py.

layers += {'2': dict(type='MaxPoolLayer', kernel_size=(2, 1), stride=(2, 1), padding=(0, 0))} # ... and add 'MY_CNN_TS_2K_NPU' to __all__
Keep the signature __init__(self, config, input_features, variables, num_classes). The pipeline fills these from your dataset, so do not hard-code them.
Input shape is (batch, variables, input_features, 1), so kernels are (k, 1).
Why padding (0, 0)? MaxPoolLayer pads k // 2 by default: 256 → 129 → 65. ONNX export of AdaptiveAvgPool(4, 1) needs a height divisible by 4, so 65 fails.
Check it
Build with get_model(...) at the real input_features, run a forward pass and export to ONNX.
Expect: output: (1, 2) · params: 1700 · onnx export: OK

Step 2 · Add the Model Description
Required: the config refers to models by their description name, not their class name
# model_descriptions/classification.py 'MY_CLS_2k_NPU': deep_update_dict(deepcopy(template_model_description), { 'common': dict( model_details='My NPU-compliant model with ~1.7k params.', ), 'training': dict( model_training_id='MY_CNN_TS_2K_NPU', # = class name model_name='MY_CLS_2k_NPU', # = dict key target_devices=[ constants.TARGET_DEVICE_F28P55, constants.TARGET_DEVICE_MSPM0G5187, constants.TARGET_DEVICE_F29H85, ], ), }), enabled_models_list = [ # ... existing models ... '...last existing entry...', # <-- ends with a comma 'MY_CLS_2k_NPU', ]
  • Start from template_model_description and override only what is specific to your model.
  • List every target_devices entry you plan to compile for.
  • The description does not need to match the config's task_type: generic models like CLS_1k_NPU serve every classification example.
Watch the comma. Without a trailing comma on the last existing entry, Python silently joins two strings and your model is reported as not supported.
Check it
get_model_description('MY_CLS_2k_NPU') returns an entry whose model_training_id is MY_CNN_TS_2K_NPU.

Guidelines for Designing Your Model
Run on the NPU, fit the device, and stay compiler-friendly
Run efficiently on the NPU
Channels in multiples of 4: 4, 8, 12, 16, ...
First conv (FCONV): 1 input channel, output a multiple of 4.
Kernels: 1D (k, 1); split large kernels into smaller ones.
MaxPool: one kernel dimension 1–4.
FC input ≥ 16 features (8-bit) or ≥ 8 (4-bit). Pool to (4, 1) when channels are few.
Global AvgPool needs > 2 spatial elements.
Full rules: docs/NPU_CONFIGURATION_GUIDELINES.md
Size the model for your device
ParametersTypical target
100 – 1KUltra-minimal MCUs
1K – 4KSmall MCUs (Cortex-M0+)
4K – 6KStandard MCUs (Cortex-M4)
6K – 13KLarger MCUs (Cortex-R5)
13K+Devices with more memory
Flash and SRAM grow with parameters; activations grow with input_features. Start small, grow only if accuracy needs it.
Compiler-friendly & naming
Prefer spec layers (ConvBNReLULayer, MaxPoolLayer, LinearLayer, ...): they export, quantize and compile cleanly.
Plain torch.nn.Module? Stick to Conv / BN / ReLU / Pool / Linear; no data-dependent control flow.
Keep quantization: 2 (TI-NPU) for NPU devices.
Names: class MY_CNN_TS_2K_NPU, description MY_CLS_2k_NPU; _NPU suffix if NPU-compliant.
